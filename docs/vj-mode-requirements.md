## 1. 目的
- 009 の「16 パッドを叩く／SEQ で組む／SET で切り替える」を、**音と同じ手つきで映像にも使う**。
- 映像は**別ウインドウ（VJ OUT）**に出し、プロジェクターで全画面にする。
- 音の楽器としての手触り（遅れの無さ・音の芯）を**一切悪くしない**。これが映像より優先（§7）。

## 2. 範囲
| 段 | 中身 | いつ |
|---|---|---|
| **Phase 1** | パッドの種類 **VISUAL**（動画・写真）、手叩き・SEQ・SET で切り替え、VJ OUT（別ウインドウ・全画面）、カット切り替え、映像の遅れ合わせ | この要件で作る |
| **Phase 2** | 動画の START / END / LOOP / 速度、2 枚の重ね（クロスフェード・ブレンド）、映像のエフェクト（モノクロ・ローファイ等） | Phase 1 を実機で使ってから |
| **Phase 3** | ネット越しに見る（同じアプリ／リスニングモード） | **検討だけ**（§10）。Phase 1 の作りで「後から足せる」形にしておく |
| 対象外 | YouTube などの配信サービスの動画を直接使う（§`youtube-trigger-study`）、カメラのライブ映像、文字入れ・テロップ、映像の書き出し（録画は OBS 等で） | — |

## 3. 用語
| 言葉 | 意味 |
|---|---|
| VISUAL パッド | 中身が動画か写真のパッド。SAMPLE / KEY / SCRATCH と並ぶ 4 つ目の種類 |
| 素材 | 取り込んだ動画・写真のファイル |
| 操作画面 | いまの 009 の画面（パッド・SEQ・SET・情報窓） |
| VJ OUT | 映像だけを出す別ウインドウ。プロジェクターに置いて全画面にする |
| 映像のきっかけ | 「パッド n を、この時刻に出せ」という小さな知らせ。操作画面 → VJ OUT に送る（§11） |

## 4. 前提（いまの 009）
- 1 ステージ＝16 セット × 4 シーケンス（A B C D）× 16 パッド。SET はポン出しで同時に鳴らせる（ミックス）。
- パッドの種類は `padKind`＝SPL / KEY / SCR。切り替えは `setPadKind` / `padKindGo`（`ui/pad-kind`）、共通の頭（SAMPLE | KEY | SCRATCH | CLOSE）。
- 音は叩いた瞬間（手叩き）か、スケジューラが少し先に予約（SEQ、先読み 0.1 秒）。パッドの点灯は `drawQueue` を rAF で消化（`ui/transport-view`）。
- `.mics` は音を base64 の WAV で持つ JSON。動画は入らない大きさ（1 分の 1080p で 100MB 超）。
- 自動保存は IndexedDB。
- 動画からの音の取り込みは既にある（LOAD が `video/*` を受ける）。

## 5. 方式の決定
### 5.1 比べた 3 案
| 案 | 中身 | 良い | 悪い |
|---|---|---|---|
| **A. パッドの種類に VISUAL を足す**（Yoshi の言う「同列」） | 1 つのセットの中で、音のパッドと映像のパッドが混ざる | SEQ・SET・COPY・MOVE・UNDO・保存が**全部そのまま使える**。1 人で音と映像を同時に演奏できる | 何もしないと重い（§7 で対策） |
| B. VJ 専用のステージ | 画面の状態に VJ を足し、16 パッドが全部映像のステージを別に持つ | 音と分かれていて分かりやすい | SEQ・SET・保存を作り直し。音と映像を同じ SEQ で合わせられない |
| C. 別アプリ（microtone VJ） | 同じ部品を使う別のページ | 重さは完全に分かれる | 2 つのアプリを育てることになる。同期に別の仕組みが要る |

### 5.2 決定（推奨）：**A＋「重いことは全部 VJ OUT でやる」**
- データと操作は A（パッドの種類 VISUAL）。音の 009 の仕組みにそのまま乗る。
- 重さの問題は、**映像の読み込み・デコード・描画を VJ OUT ウインドウだけでやる**ことで解く（§7）。
  - 操作画面は「映像のきっかけ」（数十バイト）を送るだけ。動画を再生しない。パッドに出すのは静止画のサムネだけ。
  - VJ OUT を閉じていれば、映像の負荷はゼロ（いまの 009 と同じ重さ）。
- この「きっかけだけ送る」作りが、そのまま Phase 3（ネット越し）の土台になる（§10）。

## 6. 機能要件（Phase 1）
### 6.1 素材の取り込み
| 項目 | 要件 |
|---|---|
| 入口 | VISUAL パッドの EDIT 画面の SOURCE タブ「LOAD」。いまの音の LOAD と同じ場所・同じ手数 |
| 形式 | 動画：MP4（H.264）・MOV（iPhone の HEVC は Safari のみ）・WebM。写真：JPEG・PNG・WebP・GIF（GIF は動画扱い） |
| 大きさの目安 | 動画 1080p・1 本 3 分まで（それ以上は「重いかも」と一言。止めはしない）。写真は長辺 2048px に縮めて保存 |
| 置き場 | IndexedDB の `media` ストア（素材 1 つにつき 1 件、`id`＝名前＋サイズ＋先頭の要約）。同じ素材を複数のパッドで共有 |
| 音 | 動画に音があれば、**そのパッドの音にも入れるか**を選べる（既定：入れる＝叩くと音と映像が一緒に出る）。入れない＝映像だけ |

### 6.2 VISUAL パッド
- 種類の切り替えは他と同じ（情報窓の SAMPLE ページの種類ボタン、共通の頭の SAMPLE | KEY | SCRATCH | **VISUAL**）。
- 叩く＝VJ OUT に**そのパッドの映像が出る**（動画は頭から、写真はそのまま）。
- 既定の動き（aki rule：設定なしで成立）：
  - 動画：頭から再生し、最後まで行ったら**最後のフレームで止める**（黒にしない）。
  - 写真：次の映像が来るまで出し続ける。
  - 映像の合わせ方：画面いっぱい（はみ出しは切る）。
- パッドの見た目：サムネ（動画は先頭のフレーム、写真は縮小）。種類の札は VIS。
- 情報窓の SAMPLE ページ（VISUAL のとき）：波形の代わりにサムネとファイル名・長さ。
- EDIT 画面（VISUAL）：Phase 1 は SOURCE（LOAD / DELETE）と「音を入れる／入れない」だけ。TRIM / CHOP 相当は Phase 2。

### 6.3 SEQ
- VISUAL パッドのステップは、音のパッドと同じに打ち込める・鳴る（＝映像のきっかけが出る）。
- 時刻は音と同じ予約時刻で送る（§8）。点灯と同じ精度で映像が切り替わる。
- MUTE / SOLO は映像にも効く（ミュートしたパッドは映像も出さない）。

### 6.4 SET
- SET を切り替えたら、そのセットの VISUAL パッドに切り替わる（素材は共有なので読み込み直しは無し）。
- SET のポン出しで**複数のセットを同時に鳴らしているとき**：映像は「最後にきっかけを出したもの」が勝つ（Phase 1）。セットごとの重ねは Phase 2。
- SET を止めたら（■）、VJ OUT は**最後のフレームのまま**（黒にはしない。黒は §6.5 の BLACK で）。

### 6.5 VJ OUT（出力ウインドウ）
| 項目 | 要件 |
|---|---|
| 開き方 | メニュー（新しいジャンル **VJ**）の「VJ OUT を開く」。別ウインドウで開く。開いている間は操作画面に小さな印（VJ ●） |
| 全画面 | VJ OUT の中をタップ／クリックで全画面（ブラウザの決まりで、本人の操作が要る）。Esc で戻る |
| プロジェクター | PC：ウインドウをプロジェクターの画面へドラッグして全画面。Chrome / Edge は「この画面に出す」で直接置ける（使えれば） |
| 何も出ていないとき | 黒。左下にごく小さく microtone のロゴ（OFF にできる） |
| BLACK | 操作画面から VJ OUT を一瞬で黒にするボタン（メニューの VJ ＋ 割り当てたキー）。もう一度で戻る |
| 縦横比 | 16:9 を基準に、ウインドウの形に合わせる（はみ出しは切る／Phase 2 で「全体を入れる」も） |
| 閉じたとき | 操作画面は何事もなく続く。開き直せば、いまの映像から再開 |
| 操作 | VJ OUT には**ボタンを出さない**（プロジェクターに映るので）。マウスを止めるとカーソルも消す |

### 6.6 重なり・切り替え（Phase 1）
- **1 枚だけ・カット**（最後のきっかけの映像に、その瞬間に替わる）。
- 同じパッドをもう一度叩く＝頭から（音のワンショットと同じ）。
- チョークは映像には効かない（1 枚なので意味が無い）。Phase 2 の重ねで考える。

### 6.7 保存・読み込み
- `.mics` に**素材は入れない**。パッドには参照だけ（`visual:{id,name,size,type,dur,w,h}`）。
- 読み込んだとき IndexedDB に `id` の素材があれば映像が戻る。無ければパッドに「素材を選び直す」（音は鳴る）。
- 素材の持ち運び（別の端末へ）：Phase 1 は**選び直し**。Phase 2 で「素材をまとめて書き出す（.zip）」か、既存の **Dropbox ステージ共有**のフォルダに置く形を検討。
- UNDO / COPY / MOVE（EDIT のドラッグ）は音のパッドと同じに効く（参照ごと動く）。

## 7. 重さへの対策（非機能・性能）— いちばん大事
### 7.1 仕組み
```
操作画面（いまの 009）                         VJ OUT（別ウインドウ）
  パッド / SEQ / SET ──映像のきっかけ──▶ BroadcastChannel("mics-vj") ──▶ 素材の読み込み・デコード・描画
  （サムネだけ・動画を再生しない）                                       （<video> / <img> / canvas）
  音の道（AudioWorklet）は今のまま
```
- 操作画面の仕事は「きっかけを 1 つ送る」だけ（1 回 1ms 未満）。
- VJ OUT は**別の閲覧単位**として開く（`noopener`）＝ブラウザが別のプロセスに分けやすい。同じ出どころ（オリジン）なので BroadcastChannel は届く。
- 素材は VJ OUT が IndexedDB から直接読む（操作画面を経由しない）。
- 動画のデコーダは同時に使える数に限りがある（特に iPhone / iPad）。VJ OUT は**出しているもの＋次に来そうなもの（SEQ の先読みで分かる）＋最近のもの**だけ用意し、残りは閉じる（目安：同時 4 本）。

### 7.2 数値の予算（合否）
| 項目 | 基準 | 測り方 |
|---|---|---|
| 音のスケジューラの余裕 | VJ OUT で 1080p の動画を 4 本回しても、**いまと同じ**（最小余裕が v0.3.226 の測定 72ms から落ちない） | CDP の測定（§216 と同じ方法） |
| 叩いてから音の予約まで | いまと同じ（アプリ側 0ms 追加） | event-timing |
| きっかけを送る処理 | 1 回 1ms 未満（操作画面のメインスレッド） | Performance 計測 |
| 叩いてから VJ OUT に絵が出るまで | 中央値 50ms 以内（PC）、100ms 以内（iPad）。映像の遅れ合わせ（§8）で音と揃えられること | 写真のパッドで計測、動画は `requestVideoFrameCallback` |
| VJ OUT を閉じているとき | 映像に関わる負荷ゼロ（素材を読まない・タイマーも回さない） | CPU プロファイル |
| メモリ | 操作画面はサムネだけ（16 枚 × 数十 KB）。VJ OUT は同時 4 本まで | `performance.memory`（Chrome） |

### 7.3 それでも重いときの逃げ道
- 解像度の目安を超える素材は一言で知らせる（取り込みは止めない）。
- 「VJ OUT を軽く」設定（720p に縮めて出す）。
- 同じ端末でつらいときは、VJ OUT を**別の端末**で開く（＝ §10 のリスニングモードの最初の形。同じ LAN 内）。

## 8. 時間合わせ
- 映像は音より遅れて見える（ブラウザの描画 1〜2 フレーム＋プロジェクターの遅延 30〜100ms）。音も出力の遅れがある（いまのメニューの Latency に出ている値）。
- きっかけは **「いつ出すか」の時刻つき**で送る（音の予約時刻を `AC.getOutputTimestamp()` で画面の時計に直したもの）。VJ OUT はその時刻に合わせて替える。
- メニュー VJ に **映像の遅れ合わせ（−200〜+200ms、既定 0）**。プロジェクターに合わせて手で寄せる。
- 手叩きは「いま」なので先回りできない。手叩きの映像は遅れ合わせの分だけ遅く出る（＝音と揃う方向）。

## 9. 端末ごとの出力
| 端末 | VJ OUT の出し方 | 見込み |
|---|---|---|
| PC（Chrome / Edge） | 別ウインドウ → プロジェクターの画面へ → 全画面。「この画面に出す」も使える | ◎ 本命 |
| PC（Safari / Firefox） | 別ウインドウ → ドラッグ → 全画面 | ○ |
| iPad（外部ディスプレイ＋ステージマネージャ、M1 以降） | 別ウインドウを外部ディスプレイ側に置いて全画面 | △ 実機で確かめる |
| iPad（それ以外）・iPhone | 画面のミラーになる（操作画面ごと映る）。**単独では成立しない** | × → 別の端末で VJ OUT を開く（Phase 3 の LAN 版）か、PC を出力役に |

## 10. ネット越しに見る（Phase 3・検討だけ）
### 10.1 2 つの見せ方
| 方式 | 中身 | 良い | 悪い |
|---|---|---|---|
| **きっかけを送る**（推奨の土台） | VJ OUT と同じ「映像のきっかけ」を、BroadcastChannel の代わりにネットで送る。見る側は**同じアプリのリスニングモード**（VJ OUT と同じ画面）で、自分の端末の素材を出す | 画質はそのまま・軽い・遅れ少ない・人数が増えても軽い | 見る側に**素材を先に渡す**必要がある（Dropbox ステージ共有の流用が候補） |
| 映像そのものを送る | VJ OUT の画面を配信する（WebRTC、または OBS → 配信サービス） | 見る側は URL を開くだけ | 画質が落ちる・遅れる（WebRTC 1 秒未満、配信サービス数秒〜）・中継の仕組みとお金が要る |
- 音も届けるなら、見る側でも音を鳴らす（きっかけ方式なら同じ 009 が鳴らせる）か、音を配信に乗せる。

### 10.2 Phase 1 でやっておくこと（後から足せるように）
- 映像のきっかけの形（§11）を**決めて固定**し、送る口を 1 つにまとめる（`vjSend(event)`）。中身の運び方（BroadcastChannel／ネット）は差し替えられるようにする。
- VJ OUT の画面は「きっかけを受けて素材を出すだけ」の 1 ページにする（＝そのままリスニングモードになる）。
- 素材の `id` を端末によらず同じになるように決める（名前＋サイズ＋先頭の要約）。

### 10.3 決めずに残すこと
- 中継の仕組み（自前の小さなサーバー／外部サービス）、見る側の入り方（部屋の番号・URL）、人数の上限、お金。

## 11. 映像のきっかけ（内部の形・案）
```js
// 操作画面 → VJ OUT（BroadcastChannel "mics-vj"、Phase 3 ではネット）
{ v:1, type:"show",  at:12345.6, set:3, pad:5, media:"<id>", from:0, rate:1 }   // at＝画面の時計（ms）。from＝動画の何秒目から
{ v:1, type:"black", on:true }
{ v:1, type:"stage", sets:[ {set:3, pads:{5:{media,type}} } ] }   // 開いたとき・SET 切替・素材の差し替えで丸ごと送る
{ v:1, type:"hello" } / { v:1, type:"state", ... }               // VJ OUT が開いたら今の状態をもらう
```

## 12. 受け入れ基準（Phase 1）
1. VISUAL パッドに動画・写真を LOAD できる。パッドにサムネが出る。音を入れる／入れないを選べる。
2. 手叩きで VJ OUT の映像が替わる。同じパッドの再叩きで頭から。
3. SEQ の VISUAL ステップで、再生中に映像が替わる。MUTE / SOLO が効く。
4. SET を切り替えると、そのセットの映像に替わる。
5. VJ OUT を開く・全画面・閉じる・開き直すができる。閉じても操作画面は止まらない。BLACK が効く。
6. §7.2 の数値をすべて満たす（CI の検査に入れる：音のスケジューラの余裕、きっかけの処理時間、VJ OUT を閉じたときの負荷ゼロ）。
7. 保存→読み込み直しで、同じ端末なら映像が戻る。素材が無い端末では「選び直す」が出て、音は鳴る。
8. 映像の遅れ合わせで、PC＋プロジェクターの実機で音と映像が揃う（目で見て）。

検査（`tools/check.mjs` に足す予定）：WebCodecs で作った短い webm と PNG を使う（`video-pad-study` と同じ方法で CI で動く）。VJ OUT は Playwright で 2 つ目のページとして開き、きっかけの受け取りと切り替えの時刻を測る。

## 14. 決めてほしいこと（Yoshi）
1. **方式**：パッドの種類に VISUAL を足す（§5.2、推奨）でよいか。VJ 専用のステージ（案 B）にはしない。
2. **動画の音**：VISUAL パッドに動画を入れたとき、既定で音も鳴らす（入れる）でよいか。
3. **重なり**：Phase 1 は 1 枚・カットだけでよいか（クロスフェードは Phase 2）。
4. **素材の持ち運び**：`.mics` には入れず、別の端末では選び直し（Phase 1）でよいか。
5. **最初の出力先**：PC＋プロジェクターを本命にし、iPad の外部ディスプレイは「実機で動けば」扱いでよいか。
6. **名前**：パッドの種類は VISUAL（札は VIS）、出力ウインドウは VJ OUT、メニューのジャンルは VJ でよいか。

## 15. 8 ロールで見た懸念
- **producer**：Phase 1 を「PC＋プロジェクターで、叩いて・SEQ で・SET で映像が替わる」に絞る。ネット越しは土台（きっかけの形）だけ。
- **sound**：音の道は触らない。映像の処理を音のスレッドにもメインスレッドにも載せない（§7）。動画の音を入れるときは今の LOAD と同じ 12bit/26kHz。
- **player**：手叩きの音の遅れは増やさない（数値で守る）。映像は「ついてくる」ものとし、遅れ合わせで揃える。
- **feel（aki rule）**：LOAD して叩けば映る。VJ OUT は「開く」1 手、全画面はそのウインドウをタップ。設定は既定で成立。
- **ui**：操作画面のレイアウトは変えない（パッドのサムネ・種類の札・情報窓の中身が替わるだけ）。VJ OUT にはボタンを出さない。
- **artware**：何も出ていないときの黒とロゴ、サムネの見え方、VIS の札。Phase 2 のエフェクト（モノクロ・ローファイ・走査線）で microtone の世界観に寄せる。
- **qa**：WebCodecs で素材を作れるので CI で検査できる。2 つのウインドウの間のきっかけと時刻を測る検査を足す。§7.2 の数値を関門に入れる。
- **code**：新しい部品は `audio/` ではなく `ui/vj-*`・`data/media`。`padKind` に `VIS` を足すので、`padKind==="SPL"/"KEY"/"SCR"` を見ている 10 か所を洗う。VJ OUT は単独の HTML（`vj-out.html`）として公開物に足す（ビルドに 1 枚追加）。
