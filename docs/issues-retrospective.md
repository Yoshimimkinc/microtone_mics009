# MICS009 問題点レトロスペクティブ（〜v0.3.40）

screen-spec.md §0-54 の記録を「再発防止に効く分類」で整理したもの。詳細な個別記録は screen-spec.md を参照。

## A. 音・エンジン系（楽器としての致命傷）

| 問題 | 原因 | 対策 | 版 |
|---|---|---|---|
| Mic録音すると全体音量が落ちる | `getUserMedia({audio:true})`＝AECデフォルトONで、ブラウザが「通話中」とみなし出力をダッキング | echoCancellation/autoGainControl/noiseSuppression を全OFF | v0.3.37 |
| 録音が表示されるのに鳴らない | 同上（AECがマイクをゲート→ほぼ無音で録れる） | AEC OFF＋無音ガード | v0.3.38 |
| 演奏（キー発音）が重い | selectPadの重いUI同期が発音経路に同居 | rAF集約で発音とUI更新を分離 | v0.3.21 |
| レイテンシ | SSM2044 Workletを全グループに通していた | 上物(g0/g1)はバイパス | v0.3.23 |

**教訓**: 発音経路に「音以外の仕事」を混ぜない。ブラウザの"通話向け"デフォルトはサンプラーには全部害。
**追記(v0.3.72)**: 「自動有効化」も同罪。外部ハード(S2400=USBオーディオ+MIDI複合機)接続時、起動時の
マルチアウト自動検出がドライバを巻き込みシステムフリーズ、MIDI常時受信が外部シーケンサーのノートを
全発音（勝手に同期）。ハードに触る機能は必ずユーザーの明示ONにする。

## C. 状態の二重管理・UI迷子系（設計レベル）

| 問題 | 対策 | 版 |
|---|---|---|
| 同じ状態（音量/mute）が3画面から編集できて同期バグ | MIX画面を廃止＝Single Source of Truth化 | §8 |
| 8×2と4×4で再生ボタン位置が違う・用途が説明されない | 8×2レイアウト自体を撤去して4×4一本化 | v0.2.30 |
| PADS⇔SEQ切替で縦幅/タブがジャンプ | サイズ共通化 | v0.3.12/15 |
| STEPモードとP-LOCKの操作系が競合 | STEP廃止→Digitaktモデルに確定 | v0.3.11 |
| COPY/DUPの重複 | COPY汎用化＋「元→先で自動オフ」 | v0.3.29/34 |

| 見えないのに値だけ書かれるノブ群（ゾンビUI） | CSSで全レイアウト非表示になった後もDOM/ハンドラ/同期コードが残存 | strip-ctrlsの編集UIを削除、入口は情報窓1本 | v0.3.82 |

| SEQのパターン/小節が押しても選べない | 範囲指定（開始行〜次のfunction）でのコード削除が、隣にあった生きたクリック登録を巻き込んだ | 復元＋`tools/lost-listeners.mjs`で全数比較 | v0.3.96 |

| タッチで EDIT→パッドの直後に ✂TRIM が勝手に発火 | touchend 後に合成される click が指の位置のモーダルに落ちる（ゴーストクリック）。マウスのテストでは出ない | 開いてから450msはモーダル内 click を飲む | v0.3.98 |
| 演奏しながら編集→閉じると全部消える | 「演奏中は自動保存しない」＋ pagehide は非同期IDBを待たない | WAVエンコードをキャッシュして演奏中も書く／変更から5秒で必ず一度書く | v0.3.98 |
| Load した .mics が次回起動で消える | Load 経路が dirty を立てず、古い自動保存が勝った | Load後に即 autosaveNow(true) | v0.3.98 |

**教訓(v0.3.98・全件検査)**: **1人で見ると同じ穴を同じように見落とす**。6セクションに分けて並列で総当りしたら、
3バージョン潜伏のバグの他に高6件・中10件が出た。マウスで通るテストはタッチの事故（ゴーストクリック）を
見ない。「テストが見ていない操作」を列挙する役（qa）を置き、関門（gate）で機械的に止める。

**教訓(v0.3.96)**: **範囲指定でコードを消さない**。`s.index(開始)`〜`s.index(次のfunction)` のような
削除は、間に別の生きたコードがあると黙って一緒に消える。消す時は「消す文字列そのもの」を書いて
1件ずつ消す。そして消した後は `node tools/lost-listeners.mjs` で
「消えたリスナ登録・関数・要素参照」を前の版と全数比較し、意図しないものが無いか確認する。
この事故は **id持ちの要素が window の暗黙グローバルになる**せいで、参照だけは動いてしまい
エラーも出ず、3バージョン（v0.3.84〜0.3.95）気づけなかった。

**教訓**: 「同じものを2箇所から操作できる」は必ず同期バグになる。機能を直すより片方を消す判断（MIX廃止・8×2廃止・STEP廃止）が効いた。aki ruleとも一致。
**追記(v0.3.82)**: 重複入口を畳む前に「実際に見えているか」を測ると、片方が既に**死んでいる**ことがある。
`display:none` で隠す対処を重ねると、UIは消えてもDOM・イベント・同期コードは生き残り、棚卸しの表を読み違える。
隠すのではなく消す。

## 総括：3つの繰り返しパターン

1. **ブラウザのデフォルトは楽器の敵**（AEC・autoplay・html scroll・セーフエリア）
2. **デスクトップCSSのモバイル漏れ**が最頻出。「特異度で上書き」の積み重ねになっており、モバイル用リセットを一箇所に集約する余地あり
3. **UIの重複＝バグの温床**。「消す」判断が一番効果的だった
