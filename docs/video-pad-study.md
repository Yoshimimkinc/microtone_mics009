# 動画ファイルをパッドで叩く（VIDEO パッド）の検討（2026-09-21 / v0.3.138 時点）

producer：「YouTube ではなくて、保存した動画データをサンプラーのようにパッドで演奏するのはどうか」。
**結論を先に**：**できる。しかも今の音の道をそのまま使える。** 音は既に動画ファイルから取り出している（LOAD は `video/*` を受ける）。
足すのは「映像」だけ＝ミュートした `<video>` を、パッドを叩いた瞬間にその位置へ seek する。
ローカルの動画は seek が速く（この環境の実測：`seeked` まで中央値 0.3ms、フレームが出るまで 13〜17ms）、
ミュート再生は iOS でも自動再生規制に掛からない。YouTube 案（`docs/youtube-trigger-study.md`）の弱点が全部消える。

## 1. どう見えるか
- 動画（mp4 / mov / webm）を LOAD すると、いつもどおり音がパッドに入る（12bit/26kHz・START/END・CHOP・P-LOCK・書き出し）
- 加えて **窓（情報窓の場所）に動画が出る**。パッドを叩くと **音と同時に映像がその位置へ飛ぶ**
- **CHOPPY で 16 スライス**にすると、16 パッドが 16 の「映像の頭出し」になる＝ビデオ・ジャグリング／VJ の見た目
- SEQ で打ち込めば、ビートに合わせて映像が切り替わる。ループ系はその区間を映像もループ
- iPhone でも動く（ミュート＋`playsinline` の `<video>` は操作なしで再生できる）

## 2. いまある物
| 物 | 場所 | 使い方 |
|---|---|---|
| LOAD が `video/*` を受け、`decodeAudioData` で音声だけ取り出す | `52-chop`（`#samp`） | そのまま。**動画の 0 秒 ＝ 音の 0 秒** なので、パッドの START（`t.start`、0..1）から映像の時刻が出る |
| decode できない動画を実時間再生して録る `extractViaPlayback` | `10-engine-core` | 既に `<video>` を作って再生している。映像の表示はこれを育てる |
| 手叩きの入口 `trigger` → `hitVoice`、シーケンサーの点灯 `drawLoop`（`drawQueue` を rAF で消化） | `21-voice` / `ui/transport-view` | 映像の seek は **点灯と同じ場所**（発音の時刻に合わせて表示側で）に足す |
| 全画面 iframe ＋ ✕ / ESC の枠（GTR） | `70-sampling` | 全画面 VJ 表示の枠に流用 |
| 自動保存（IndexedDB） | `60-autosave` | 動画の Blob もここに入れられる（`.mics` には入れない、§5） |

## 3. 実測（この環境の Chromium、640×360 VP8、12 秒、ローカル）
`tools/` には置いていない PoC（WebCodecs で動画を作り、Playwright で seek を測った）。キーフレーム間隔 1 秒と 3 秒の 2 本。

| 状況 | `seeked` まで（中央値 / p90 / 最悪） | 新しいフレームが出るまで |
|---|---|---|
| 停止中に `currentTime=` | 0.3 / 0.9 / 2.4 ms | 15〜17 ms（1 フレーム） |
| 再生中に `currentTime=`（シーケンサーで叩かれる状況） | 2.5 / 3.0 / 3.7 ms | 13.2 ms |
| 60ms 間隔で 16 連打 | 合計 964 ms（＝16×60。**取りこぼし無し**） | — |

キーフレーム間隔 1 秒と 3 秒で差なし（小さい動画なので前のキーフレームからの復号が軽い）。
**実機（iPhone の 1080p H.264）は数十 ms になりうる**が、YouTube の 100〜400ms とは桁が違う。`tools/video-seek-probe.html` で実機を測る（§7）。
Chrome には `fastSeek`（最寄りキーフレームへ）が無い。Safari にはある＝iPhone ではさらに速くできる余地。

## 4. 作り（案）
### データ
- `tracks[i].video = { id, offset }`：`id` は読み込んだ動画の識別（名前＋サイズ＋先頭のハッシュ）、`offset` は音の 0 秒が動画の何秒か
  （通常 0。保存時に音を `start-1s..end+1s` に**切り詰める**（`calcCrop`）ので、その分を `offset` に足す）
- 動画そのもの（Blob）は **`videos` ストア（IndexedDB）** に `id` で 1 つ。同じ動画から作った 16 パッドは 1 つを共有
- 映像の時刻 ＝ `offset + t.start × 音の長さ`（叩いた瞬間）。ループ系は `loopStart..end` を映像もループ

### 表示
- **1 動画につき 1 つの `<video muted playsinline preload=auto>`**。同時に見せるのは 1 つ（最後に叩いたパッドの動画）
- 置き場は **情報窓（`.perf-screen`）の位置**に切り替えで出す（窓の寸法は動かさない＝不変性 §94）。スマホは波形ストリップの位置。
  全画面（VJ）は GTR の枠（✕ / ESC）で、パッドは下に残す（両手で叩ける）
- 叩く：`hitVoice` の呼び出し側（`trigger` / SEQ 行名）で `videoCue(i)`。シーケンサー：`drawLoop` の `hits` で `videoCue`（発音時刻に同期＝点灯と同じ精度）
- 止める：ノートの終わり（END）で `pause`。ワンショットは END で止め、最後のフレームを残す（黒にしない＝映像が「切れる」感じを出さない）
- 音を出す処理に映像を混ぜない（`21-voice` は触らない。表示側だけ）＝ Phase 2 の「描画は描画関数だけ」の規則どおり

### 保存
- **`.mics` には動画を入れない**（1 分の 1080p で 100MB 超。JSON+base64 では無理）。`video:{id,name,size,offset}` だけ書く
- 読み込んだとき、IndexedDB に `id` の動画があれば映像が復活。無ければ「動画 `name` を選び直す」（音は鳴る＝映像なしで困らない）
- 共有（`73-share-export`）は音だけ（今と同じ）

### 制限（最初の版）
- 同時に持てる動画：4 本まで（メモリ。1080p 3 分で 200〜400MB になりうる）。超えたら古いものから外す（音は残る）
- 解像度は端末任せ。iPhone の 4K は `<video>` が重い → 案内「1080p 以下・3 分以内が軽い」

## 5. 段階
| 段 | 中身 | 検査（`check.mjs`） |
|---|---|---|
| 1 | LOAD した動画の Blob を保持し、窓に `<video>` を出す。**手叩きで seek**。EDIT の START/END を動かすと映像も追従 | WebCodecs で作った webm を `#samp` に入れ、叩いて `currentTime` が START に一致・0 errors |
| 2 | CHOPPY → 16 パッドの映像頭出し。SEQ の `drawLoop` から seek。ループ系の映像ループ | 再生中に `currentTime` がステップごとに動く |
| 3 | IndexedDB に動画を保存、`.mics` に `video` を書く、選び直し | 保存→再読込で映像が復活／無ければ音だけ |
| 4 | 全画面 VJ（GTR の枠）、スマホの置き場 | 不変性（§94）・画面予算・44px |

段 1 だけで「動画をサンプラーのように叩く」は成立する。ここまでを 1 版（v0.3.13x）で出せる大きさ。

## 6. 8 ロールで見た懸念
- **player**：映像は 1 フレーム（13〜17ms）遅れて出る。音は今までどおり 0 遅延なので手触りは変わらない。映像はあくまで「ついてくる」
- **feel（aki rule）**：LOAD に動画を入れるだけで映像が出る＝新しい操作を覚えない。全画面は「動画をタップ」1 手
- **ui**：窓の寸法は動かさない（表示の切替だけ）。スマホでは波形ストリップと排他
- **sound**：音の道は不変。`<video>` はミュート（`AC` に繋がない）＝ローファイ鎖に混ざらない
- **qa**：WebCodecs で動画を作れるので **CI で自動検査できる**（YouTube 案はできなかった）
- **artware**：動画の縁・角丸・モノクロ／ローファイのフィルタ（CSS `filter`）で MICS の世界観に寄せられる（値は後で）
- **producer**：権利は「自分の動画」が前提。共有は音だけなので `.mics` の扱いは今と同じ

## 7. 実機で測ること
`tools/video-seek-probe.html`：手元の動画を選び、停止中／再生中の seek を 20 回ずつ測る（PC・iPhone）。
```sh
python3 -m http.server 8137
# PC:      http://localhost:8137/tools/video-seek-probe.html
# iPhone:  http://<PCのLAN IP>:8137/tools/video-seek-probe.html
```
見るもの：iPhone の 1080p H.264 で「フレームが出るまで」の中央値（**50ms 以内なら段 1 へ**）、4K で重くないか。

## 8. 決めてほしいこと
1. 映像の置き場：情報窓の位置（PC）／波形ストリップの位置（スマホ）でよいか。全画面 VJ は段 4 でよいか
2. `.mics` に動画を入れない（IndexedDB に置き、無ければ選び直し）でよいか
3. 同時 4 本・1080p 目安の制限でよいか
