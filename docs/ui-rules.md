# 楽器UIの開発規則（MICS009）

作文で終わらせないために、**数値と測り方をセットで**書く。
測れるものは `tools/ui-audit.mjs`（スコア）と `tools/check.mjs`（合否）に入れる。
測れないものは「6ロールのセルフレビューで見る項目」として明記する。

## 0. 原則
1. **楽器はまず鳴る**。演奏に関わるものが常に最優先。設定は奥へ。
2. **画面は動かない**。状態が変わっても寸法が動かないこと（機械が跳ねる楽器は無い）。
3. **嘘をつかない**。インジケーターは実測を映す。合成した数字を出さない。

---

## 1. 情報提供の基準

| 項目 | 基準 | 測り方 |
|---|---|---|
| 常時見えるもの | 現在地（PAT/BAR/STEP）・選択中の対象・再生状態・編集中の値 | 目視 |
| 反応の速さ | 見た目 ≤1フレーム(16ms) / 音 ≤10ms | Performance計測 |
| 値の表示 | 必ず単位を添える（st / dB / ms / % / Hz） | 目視 |
| 桁の扱い | 数字は tabular-nums ＋ 最大桁で固定幅。値を変えても幅が動かない | check.mjs |
| メッセージ | 窓は1行で切る（全文はトースト）。トーストは 2s＋40ms×文字数、上限8s | 目視 |
| ヒント | 常時表示しない。**モードに入っている間だけ**出す | 目視 |
| 正直さ | LED＝実際の着信、VU＝実測値。「それらしい動き」を作らない | コードレビュー |

> 破った例：Master VUが実測でなく合成だった（未修正・宿題）。

## 2. 操作の基準

| 項目 | 基準 | 測り方 |
|---|---|---|
| 触れる大きさ（演奏系） | **44×44px 以上**（パッドは64px以上） | ui-audit |
| 触れる大きさ（二次操作） | 32×32px 以上 | ui-audit |
| 手数 | どの機能も **3タップ以内**。常用は2、演奏中の操作は1 | 目視で経路を数える |
| モード | **トグル**。押しっぱなしを要求しない（両手が塞がる） | コードレビュー |
| Undo | 1操作＝1手。ドラッグは連続しても1手 | check.mjs |
| 既定値 | 数値欄はダブルタップで0。列挙はタップで送る（リセットしない） | check.mjs |
| 入口 | 同じ値の編集入口は**1つだけ** | deadcss＋目視 |
| 破壊的操作 | 名前で分かる（TRIM/CHOP/REV）＋必ずUndo可 | コードレビュー |
| 誤爆防止 | 起動タップ後450ms遮断／ハンドルは±26pxでのみ掴む | 目視 |

## 3. 視認性の基準（スコア化）

役割で基準を変える。全部を4.5:1にすると計器らしさが死ぬので、**値だけは絶対に守る**。

| 役割 | 例 | 最小サイズ | 最小コントラスト |
|---|---|---|---|
| **値** | 数値・パッド名・状態・**現在地を示すラベル** | 11px | **4.5:1** |
| ラベル | PITCH / BPM などの**欄の見出し** | 9px | 3:1 |
| 装飾 | ブランド名・型番・ハンドルのキャップ | 8px | 2:1 |

> **「現在地を示すラベル」は値**（v0.3.95で明確化）。ソフトキー（MAIN/SAMPLE/TONE/FX/ASSIGN）や
> モードボタンは、名前が付いているだけの飾りではなく「いまどのページに居るか」という**状態の表示**。
> 読めなければ迷子になるので、欄の見出しと同じ9px/3:1では足りない。
> 非選択のものも読める濃さにすること（`opacity` で薄くして基準を割らない）。

- 色だけで意味を伝えない（形・位置・文字を併用する）
- **視認性スコア** = 100 −（値のコントラスト不足×6）−（ラベル/装飾の不足×1）−（サイズ不足×4）

## 4. 両手操作の基準（難易度）

| 項目 | 基準 |
|---|---|
| 役割分担 | 左手＝モード/選択、右手＝演奏。**入れ替えを強要しない** |
| 親指の到達域 | 演奏に要るものは画面の**下2/3**（縦持ち） |
| 同時押し | 2点の距離は画面幅の70%以内（片手で届く） |
| 保持操作 | 「押しながら」を必要とする操作を**2つ同時に要求しない** |
| **難易度スコア** | 1操作あたり `必要な指の数 + 移動距離/画面幅 + (保持が要るなら1)` の合計。**2.0以下**を合格 |

例：P-LOCK（パラメータを押しながらパッド）＝ 指2 + 0.4 + 1 = 3.4 → **重い**（宿題）

## 5. 時間の基準（レイテンシ予算）

| 経路 | 予算 |
|---|---|
| パッド→発音 | 10ms（実測中央値 0ms） |
| 入力→見た目 | 16ms（1フレーム） |
| スケジューラ先読み | 100ms（メインスレッドが詰まっても遅れない） |
| 起動→触れる | 2.5s（スプラッシュ含む） |

## 6. 不変性の基準（機械検査済み）

**状態が変わっても、窓・メニュー・キー・パッドの `[幅, 高さ, x, y]` が1pxも動かない。**
検査する状態：5ページの切替 ＋ 長文メッセージ ＋ ヒント ＋ 素 の8通り × 5幅。
→ `tools/check.mjs`（1つでもズレたら exit 1）

## 7. 可逆性と安全

| 項目 | 基準 |
|---|---|
| Undo | すべての編集操作が1手で戻る |
| 保存 | 非破壊。書き出しは元を壊さない |
| 外部機器 | ハードに触る機能（MIDI受信・マルチアウト検出）は**明示ONのみ**。既定OFF |
| 音の安全 | 起動時は無音。演奏中のダッキングは **1dB以内**。最終段でクリップ防止 |
| 劣化 | 機能が無い環境では黙って代替に落ちる（AudioWorklet→biquad） |

> 破った例：起動時のマルチアウト自動検出でシステムごとフリーズ（S2400事件・v0.3.72で修正）

## 8. 静けさ（騒がしさの上限）

- 常時アニメーションしている要素は **1個以下**
- 同時に出るメッセージは1つ。ヒントとメッセージは同じ行を共用する
- 「常時チートシート」を出さない

## 9. 画面予算

| 領域 | 予算 |
|---|---|
| パッド（主役・縦持ち） | 画面面積の **30%以上** |
| パッド（Performance Mode・横widescreen） | **20%以上** |
| 情報窓 | **25%以下** |
| モーダル | 入り組んだ設定のみ。音作りは表 |

> 横widescreenで30%に届かないのは形の問題。16パッドを8×2に広げると1枚が横長になり、
> 面積を稼ぐには縦を食うしかない。上の計器（情報窓・P-LOCK・PAT/BAR・16ステップ）を全部残したまま
> 800px高で取れる上限が実測 **21.6%** だったので、横は20%を基準にする（v0.3.93）。
> 縦持ちは32%出ているので30%のまま。

## 10. 検査方法

```sh
node tools/check.mjs                                  # 合否（exit 1 で落ちる）
node tools/ui-audit.mjs                               # スコア（レポート専用）
node tools/deadcss.mjs | node tools/deadcss-filter.mjs # 未使用CSS
```

`ui-audit.mjs` の測定で踏んだ罠（同じ間違いをしないこと）：
- Chromeは色を `color(srgb 0.25 0.66 0.35)` 形式でも返す。0-255として読むと真っ黒になる
- 背景が**グラデーション**だと `backgroundColor` は透明。`background-image` の最初の色を見る
- 半透明の背景と `opacity` を合成しないと、読める文字を 1:1 と誤判定する

## 11. 現状スコア（v0.3.93 実測）と宿題

| | 390×844 | 1280×800 |
|---|---|---|
| 視認性 | 38 → 68 → **72** | 0 → 50 → **54** |
| 触れる | 44 → **64** | 24 → **44** |
| 静けさ | 100 | 100 |
| 画面予算 | 100 | 70 → 83 → **81** |

**片づいたもの（v0.3.93）**
1. ✅ **パッド名のコントラスト**：空パッドの `opacity:.55` を撤去して 2.53→5.15:1。
   「空」は＋アイコンが示しているので薄字にする理由が無かった。あわせて波形の上でも輪郭が残るよう
   パッド面色のハローを敷いた（コントラスト計算には出ないが、実際に読みにくかったのはここ）。
4. ✅ **デスクトップのパッド面積 15.2%→21.6%**（パッド1枚の高さ 83→115px、1024幅では 67→99px）。
   情報が無い行——情報窓のブランド行と `PAD`/`SEQ` のセクション見出し——を perf で畳み、
   パッドの隙間を 10→6px にして面積をパッドへ返した。情報窓も 25.5%→20.6% で予算内。
   モードボタンの非選択色も 3.96→合格へ。

**残り**
2. **情報窓の欄が30〜34px**（演奏系の基準44px）。窓の高さと相談が要る
3. ✅ **ソフトキー**（v0.3.95）：10px→**12px**、34→**44px**、非選択の `opacity` .5→.72。
   §3の「現在地を示すラベルは値」に合わせた。窓は 189→199px / 204→214px、パッドは 78→75px / 115→110px
5. P-LOCKの両手難易度 3.4（基準2.0）
6. Master VUが実測でなく合成（§1「正直さ」違反）
7. `.perf-pat` / `.perf-bar` の選択中の文字が 4.26:1（基準4.5）。アクセント色を6%明るくすれば届くが、
   世界観に触るのでアートウェア担当の判断待ち

## 12. 測定器の信頼性について
このスコアは**測定器を3回直してから**の値。最初は全項目0点で、原因は全部こちら側だった。

| 誤判定 | 原因 |
|---|---|
| 情報窓の文字が全部 1:1 | Chromeは色を `color(srgb 0.25 0.66 0.35)` でも返す。0-255として読むと真っ黒 |
| 同上 | 背景がグラデーションだと `backgroundColor` は透明。`background-image` を見ていなかった |
| perfのパッド名が 3.04:1 | グラデーションの先頭が **alpha 0.09 の色味レイヤー**。これを地の色として採用していた |
| ロゴの `tone` が「値」 | `<b>` を無条件に値と判定していた |

**スコアが悪いときは、まず測り方を疑う。** 直す前に実際の色とピクセルを確認すること。
